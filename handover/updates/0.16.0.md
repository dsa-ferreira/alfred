# alfred 0.16.0 update

Turns can now wait for the user's answer before a tool call goes ahead,
asked with Telegram buttons: for tools on a user's new `confirm` list, and
for questions MCP servers ask during a call. For the infra side: a new image
tag, migration `0010` (runs on start), and two optional config keys, both
off or at their default unless set.

```yaml
handover_update: 1
service: alfred
from: 0.15.0
to: 0.16.0

before:
  - pg_dump the alfred database (0.16.0 adds migration 0010; see rollback)

changes:
  - change: changed
    path: components.alfred.image
    value: album.lan/alfred:0.16.0  # linux/amd64; see Open questions
  - change: added
    path: components.alfred.files[/etc/alfred/alfred.toml].users[].confirm
    value: {value: []}
    why: >
      Optional, per [[users]] entry. Tools whose calls on that user's turns
      wait for their "Do it" button, in the same syntax as that user's
      `tools` ("mcparr_add_media", "cookbook_*", "*"). Same startup checks
      as `tools`: an entry that isn't *, alfred_..., or a configured MCP
      server's name and _, or an exact alfred_ name that doesn't exist,
      stops alfred naming the user and the entry. An entry the user's
      `tools` can never match is only a WARNING. The owner decides who
      confirms what; leaving it out keeps today's behaviour.
  - change: added
    path: components.alfred.files[/etc/alfred/alfred.toml].input_requests
    value: {expire_after_min: 60}
    why: >
      Optional section. Minutes a question waits for its answer before its
      turn ends without running the call. Must be positive, or alfred stops
      at startup naming input_requests.expire_after_min. Checked on the
      existing [reminders] check_interval_s clock; no new setting for that.

after: []

verify:
  - "docker exec alfred alembic current  ->  0010 (head)"
  - "docker logs alfred  ->  'alfred started: ...' and 'input request expiry loop started (every 30s)', no migration error"
  - "With confirm = [\"mcparr_add_media\"] on your [[users]] entry: 'add Dune (2021)' in Telegram  ->  a message naming mcparr_add_media with its arguments and the buttons Do it / Cancel; Do it  ->  the message says Confirmed, then the reply"

clients: none
rollback: >
  1) Stop alfred. 2) Undo migration 0010 with the 0.16.0 image (0.15.0's
  entrypoint can't start on a database at a revision it doesn't know):
  docker run --rm -e ALFRED_DATABASE_URL=<same url> album.lan/alfred:0.16.0 alembic downgrade 0009
  This drops the input_requests table and marks queue items that were
  waiting for an answer, or cancelled while waiting, as failed; nothing
  else changes. 3) Remove any `confirm` keys and the [input_requests]
  section from alfred.toml (0.15.0 rejects unknown keys at startup).
  4) Pin album.lan/alfred:0.15.0. Restoring the pre-upgrade dump is the
  alternative to 2.
```

## Details

**Migration 0010** allows two new values in `queue_items.status`
(`waiting`, `cancelled`) and creates the `input_requests` table: one row per
question, with its answer, the parked turn's progress (JSON), the Telegram
message id, and a partial unique index allowing one live request per queue
item. It touches no existing rows and takes well under a second, in the
entrypoint's `alfred migrate` as before. Rows are small (a turn's tool
results so far, images dropped) and are kept like `turn_tool_calls`; the
existing database backup covers them.

**Behaviour the infra side may notice.**
- The bot now also asks Telegram for button taps (`callback_query` in its
  long-polling `allowed_updates`). Still long polling, no webhook, no new
  port; nothing to configure.
- A waiting turn doesn't hold the queue; it stays in the database across
  restarts and its buttons keep working. A restart during a confirmed call
  never runs the call again: the user gets the "may have partly completed"
  notice.
- A new asyncio task, `input-requests`, expires unanswered questions. Like
  the other loops it only reads and writes Postgres.
- Idle close (`history.idle_close_after_h`) waits for a user's waiting turn
  to be answered or expire before closing their conversation.
- Telegram calls added: `editMessageText` and `answerCallbackQuery`, same
  bot token, same host as before.

**MCP servers.** alfred now declares form elicitation when it connects, so
a server tool that asks the user no longer fails. mcparr and cookbook don't
ask today; nothing changes for them. If they start asking, the MCP SDK keeps
the question's state 600 s by default with a key lost on restart; a shared
key and longer TTL (`RequestStateSecurity`) would be set on those servers,
not here.

No new dependencies, secrets, volumes, ports or network connections.
Resource use is unchanged.
