# alfred 0.8.1 update

Reminder fixes from the first days on 0.8.0. Reminders now come due at the
start of their minute instead of up to a minute late, and alfred confirms
them in plain words without reminder numbers. For the infra side, this is a
new image tag and a tighter limit on one optional setting. There are no
migrations, and no new secrets, dependencies, connections, ports or volumes.

```yaml
handover_update: 1
service: alfred
from: 0.8.0
to: 0.8.1

before: []

changes:
  - change: changed
    path: components.alfred.image
    value: album.lan/alfred:0.8.1  # linux/amd64; see Open questions
  - change: changed
    path: components.alfred.files[/etc/alfred/alfred.toml].reminders.check_interval_s
    value: {value: 30}
    why: >
      Same default, but values must now be above 0 and at most 60. A larger
      value stops alfred at startup with an error naming
      reminders.check_interval_s. 30, or leaving the key out, is fine. See
      Details for the new meaning and the template comment.

after: []

verify:
  - "docker logs alfred  ->  'alfred started: ... reminders checked every 30s, ...' and 'reminder loop started, checking every 30s', and no 'invalid configuration' error"
  - "Owner sends 'remind me in 2 minutes to stretch'  ->  a plain confirmation naming the time, e.g. 'Very good. I shall remind you to stretch at 13:57.', with no '#' number"
  - "At that minute  ->  docker logs alfred shows '1 due reminder(s) queued as item(s) [...]' with a timestamp in the first second of the minute (hh:mm:00); the bot's message follows once the model has written it"

clients: none
rollback: >
  Pin album.lan/alfred:0.8.0. No database changes, and a check_interval_s of
  60 or less is valid on 0.8.0 too, so nothing else to undo. Reminders set
  under 0.8.1 keep working.
```

## Details

**When checks run.** On 0.8.0 alfred checked for due reminders every
`check_interval_s` counted from startup, and "in N minutes" kept the seconds
of the moment it was set. Together they made a reminder up to about a minute
late. On 0.8.1 due times are whole minutes, and checks run on the wall
clock: at the start of every minute and every `check_interval_s` within it
(`:00` and `:30` for 30). A reminder is queued in the first second of its
minute and reaches the owner once the model has written it. That takes a few
seconds, or longer if `ollama-gpu` has to wake up. Database load is
unchanged: one indexed query per check.

The comment above the key in the template can be updated to match:

```toml
[reminders]
# Time used for a reminder on a date with no clock time ("on Friday"), HH:MM.
default_time = "09:00"
# Checks for due reminders run on the clock: every whole minute and every
# check_interval_s within it (at most 60). Reminders are queued at their minute.
check_interval_s = 30
```

**Container clock.** Reminders now depend on the host clock being right to
the second. The LXC containers take their time from the Proxmox host, so this
only needs the host to keep NTP sync, as it should anyway.

**Wording.** Confirmations and delivered reminders no longer mention reminder
numbers or countdowns. Numbers appear only when the owner asks which
reminders are set. This is a prompt change, nothing to configure.
