# alfred 0.16.1 update

Fixes 0.16.0 letting another turn act on a message whose turn was waiting
for the user's answer: an `/ask` arriving meanwhile could repeat the waiting
request and ask the user a second question. For the infra side: a new image
tag only.

```yaml
handover_update: 1
service: alfred
from: 0.16.0
to: 0.16.1

before: []

changes:
  - change: changed
    path: components.alfred.image
    value: album.lan/alfred:0.16.1  # linux/amd64; see Open questions

after: []

verify:
  - "docker exec alfred alembic current  ->  0010 (head), unchanged"
  - "docker logs alfred  ->  'alfred started: ...'"

clients: none
rollback: Pin album.lan/alfred:0.16.0. No schema or config change.
```

## Details

While a turn waits for its user's answer, its entries (the user's message
that started it) are now left out of every other turn's context until it
ends; then they show again with their reply. A turn parks with the exact
entries of its context and resumes with them. Turns already waiting when
0.16.1 starts (parked by 0.16.0) resume as before.

No migration, config, secret, port or dependency changes. Waiting turns
survive the upgrade.
