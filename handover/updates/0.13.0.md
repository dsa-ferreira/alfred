# alfred 0.13.0 update

alfred now keeps short facts about each user, learned from their archived
conversations or told directly, and lists them with a new `/memory` bot
command. For the infra side: a new image tag, migration `0007` (runs on
start, adds one table), and five optional `[memory]` settings in
`alfred.toml`. After the upgrade alfred reads every archived conversation
once in the background, which means extra requests to ollama-gpu and ragman.

```yaml
handover_update: 1
service: alfred
from: 0.12.0
to: 0.13.0

before:
  - pg_dump the alfred database (0.13.0 adds migration 0007; see rollback)

changes:
  - change: changed
    path: components.alfred.image
    value: album.lan/alfred:0.13.0  # linux/amd64; see Open questions
  - change: added
    path: components.alfred.files[/etc/alfred/alfred.toml].memory.facts_in_context
    value: {value: false}
    why: >
      Optional, default false. Whether every turn's system prompt carries the
      user's facts. Leave it false for this deploy: the owner checks the
      learned facts with /memory first and turns it on later (true, then
      restart alfred).
  - change: added
    path: components.alfred.files[/etc/alfred/alfred.toml].memory.facts_context_max_chars
    value: {value: 3000}
    why: Optional, shown at its default. Most characters of facts in one prompt.
  - change: added
    path: components.alfred.files[/etc/alfred/alfred.toml].memory.fact_max_chars
    value: {value: 300}
    why: Optional, shown at its default. Longest fact.
  - change: added
    path: components.alfred.files[/etc/alfred/alfred.toml].memory.facts_extraction_max_attempts
    value: {value: 0}
    why: >
      Optional, shown at its default. Failed extractions of one conversation
      before alfred gives up on it; 0 never gives up. -1 stops alfred at
      startup with an error naming the key.
  - change: added
    path: components.alfred.files[/etc/alfred/alfred.toml].memory.facts_duplicate_max_distance
    value: {value: 0.1}
    why: >
      Optional, shown at its default. Cosine distance under which two of a
      user's facts are duplicates. Must be between 0 and 1 (exclusive), or
      alfred stops at startup with an error naming the key.
  - change: changed
    path: integrations.ollama-gpu.detail
    value: >
      Unchanged endpoint and models. New: one fact-extraction request per
      archived conversation, on the summary model, streamed, only while
      alfred's queue is quiet (same rule as summaries), cancelled when a
      message arrives.
  - change: changed
    path: integrations.ragman.detail
    value: >
      Unchanged endpoint and model. New: one embedding request per stored
      fact, made whether or not alfred's queue is busy. Retried with backoff
      while ragman is down; facts work without an embedding meanwhile.

after: []

verify:
  - "docker exec alfred alembic current  ->  0007 (head)"
  - "docker logs alfred  ->  'alfred started: ...', then over time 'conversation N facts: X added, Y replaced; ...' lines, one per archived conversation"
  - "In Telegram, the bot's command menu shows /memory"
  - "Send /memory  ->  a list of facts or 'I know no facts about you yet, sir.', without a model request"
  - "docker logs alfred | grep 'fact extraction failed'  ->  none, or few (each is a WARNING with its attempt count)"

clients: none
rollback: >
  1) Stop alfred. 2) Undo migration 0007 with the 0.13.0 image (0.12.0's
  entrypoint can't start on a database at a revision it doesn't know):
  docker run --rm -e ALFRED_DATABASE_URL=<same url> album.lan/alfred:0.13.0 alembic downgrade 0006
  This drops the facts table and the three extraction columns: every fact
  is lost. 3) Remove the five facts_* / fact_* keys from alfred.toml if they
  were added (0.12.0 rejects them as unknown keys). 4) Pin
  album.lan/alfred:0.12.0. Restoring the pre-upgrade dump is the
  alternative to 2. To keep the facts but take them out of every prompt,
  set facts_in_context = false and restart instead.
```

## Details

**Migration 0007** creates the `facts` table (with a `vector` column, using
the pgvector extension already there since 0.4.0) and adds three columns to
`conversations`: `facts_outcome` (nullable), `facts_attempts` (default 0)
and `facts_next_at` (nullable), plus two partial indexes. Existing rows are
not rewritten, and it takes well under a second. It runs in the entrypoint's
`alfred migrate`, like the earlier ones. Removed facts are only marked
removed, never deleted, so the table only grows, by a few short rows per
user per week.

**Backfill after the upgrade.** Every conversation archived before 0.13.0
starts with its facts pending. alfred reads them one at a time, oldest
first, in the background, only while no message is waiting or running and
none has finished for `memory.summary_quiet_s` (60 s by default). Each one
is a request to ollama-gpu, so the GPU box is woken and kept busy during
quiet stretches until the backlog is done. With a couple of weeks of
conversations that is a few dozen requests. Messages from users always come
first: one that arrives cancels the extraction request in progress.

**Failures.** A failed extraction logs a WARNING with the conversation and
attempt count and is retried with the queue's backoff (up to
`queue.retry_max_s`, 900 s by default). With the default
`facts_extraction_max_attempts = 0` it is never given up, and that user's
later conversations wait behind it; a steady stream of these WARNINGs for
the same conversation is the sign to look at.

**`/memory`** is alfred's first Telegram bot command. alfred registers it
with Telegram at startup (`setMyCommands`, over the existing connection to
api.telegram.org). If that call fails, alfred logs a WARNING and starts
anyway; the command still works when typed. Users whose `tools` allow-list
matches `alfred_*` (or `*`) are also offered the new `alfred_remember` and
`alfred_forget` tools; exact entries for those names are now accepted.

No new ports, dependencies, secrets, volumes or network connections.
Memory and CPU use of the container are unchanged; the database grows by
the facts table.
