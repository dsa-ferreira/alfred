# alfred 0.5.0 update

alfred now shows "typing…" in the owner's Telegram chat while it works on a
message, and it logs how large each model request is. For the infra side,
this is only a new image tag. There are no new settings, secrets,
dependencies, ports, volumes or migrations.

  - "Owner asks the bot 'what's downloading?'  ->  the chat header shows 'typing…' until the reply arrives"
  - "docker logs alfred  ->  for that message, a 'turn <n> context: system ... chars; tools ... defs ... chars (...); history ...' line and one 'turn <n> request <k>: ... prompt tokens, ... completion tokens' line per model request"
  - "docker logs alfred  ->  no 'could not send the typing indicator' warning"

rollback: >

  nothing else to undo.

## Details

**Typing indicator.** While the AI turn for an owner message runs, alfred
sends Telegram's `sendChatAction` (typing) to the owner's chat every
4 seconds. It uses the same bot token and the same outbound HTTPS connection
to `api.telegram.org` that alfred already uses, so the firewall doesn't
change. Nothing is sent while a message waits in the queue or for a retry
(for example, while `ollama-gpu` is waking up), or for service `/ask` calls.
If Telegram refuses the action, alfred logs one warning per turn
(`could not send the typing indicator: ...`) and the reply is still
delivered.

**Logging.** Each turn logs one INFO line with the size in characters of the
context it sends (system prompt, tool definitions per MCP server, history).
After each model request, it logs the token counts that `ollama-gpu` reports.
Conversation summaries get the same token line. This adds about two to five
short lines per owner message, and none of them contain message text. With
`server.log_level = "DEBUG"`, each turn also lists its five largest tool
definitions.
