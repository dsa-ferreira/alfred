# alfred 0.12.0 update

Conversations can now close by themselves after a quiet spell, and ending
one no longer makes the next message wait for its summary. For the infra
side: a new image tag, migration `0006` (runs on start), and one new line in
`alfred.toml` to turn idle close on.

```yaml
handover_update: 1
service: alfred
from: 0.11.0
to: 0.12.0

before:
  - pg_dump the alfred database (0.12.0 adds migration 0006; see rollback)

changes:
  - change: changed
    path: components.alfred.image
    value: album.lan/alfred:0.12.0  # linux/amd64; see Open questions
  - change: added
    path: components.alfred.files[/etc/alfred/alfred.toml].history.idle_close_after_h
    value: {value: 6}
    why: >
      Hours after a user's last own message before alfred archives their
      conversation and starts a new one. Optional; unset means never. 0 or a
      negative number stops alfred at startup with an error naming
      history.idle_close_after_h.
  - change: added
    path: components.alfred.files[/etc/alfred/alfred.toml].memory.summary_quiet_s
    value: {value: 60}
    why: >
      Optional, shown at its default. Seconds the queue must have been quiet
      before a summary request starts on ollama-gpu. 0 waits only for an
      empty queue.

after: []

verify:
  - "docker exec alfred alembic current  ->  0006 (head)"
  - "docker logs alfred  ->  'alfred started: ... idle close after 6h ...' and 'idle close started'"
  - "End a conversation ('thanks, we're done')  ->  the reply, then '— #N archived —' / '— new conversation #N+1 —' with no title, right away"
  - "Send a message straight after ending a long conversation  ->  answered without waiting for the old conversation's summary"
  - "Leave a conversation for more than 6 hours, then write  ->  '— #N closed after inactivity —' / '— new conversation #M —', then the reply"

clients: none
rollback: >
  1) Stop alfred. 2) Undo migration 0006 with the 0.12.0 image (0.11.0's
  entrypoint can't start on a database at a revision it doesn't know):
  docker run --rm -e ALFRED_DATABASE_URL=<same url> album.lan/alfred:0.12.0 alembic downgrade 0005
  3) Remove history.idle_close_after_h and memory.summary_quiet_s from
  alfred.toml (0.11.0 rejects them as unknown keys). 4) Pin
  album.lan/alfred:0.11.0. Conversations closed for inactivity stay
  archived and summarised; a pending "closed after inactivity" marker is
  never sent. Restoring the pre-upgrade dump is the alternative to 2.
```

## Details

**Migration 0006** adds two nullable columns to `conversations`:
`end_reason` (`user` or `idle`) and `marker_sent_at`. No backfill, no
rewrite of existing rows, no extension; it takes well under a second. It
runs in the entrypoint's `alfred migrate`, like the earlier ones.

**Idle close** runs inside the alfred container as one more background task,
only when `idle_close_after_h` is set. It needs nothing new: everything it
uses is in Postgres, so it carries on across restarts. Only the user's own
messages count. Service notices, `/ask` turns and reminders don't keep a
conversation open, and a conversation without a message from its user is
never closed. A conversation isn't closed while one of its user's messages
waits in the queue. The user is told on their next message, not at the
moment it closes.

**Summaries and ollama-gpu.** Summaries are now made only by the background
memory sweeper. A summary request starts only when no message, `/ask` or
reminder is waiting or running and none has finished for `summary_quiet_s`.
A message that arrives while a summary is being generated cancels the
summary request; it is made again at the next quiet stretch and doesn't
count as a failure. The summary request is now streamed (`"stream": true`
to `/v1/chat/completions`), because Ollama only stops work for a dropped
client on a streamed request. Chat turns are unchanged. Same endpoint and
same models, so nothing changes for ollama-gpu. Summaries still wake it
when it is suspended, as before, but now only after the queue has been
quiet. After a restart, summaries also wait one quiet period.

No new ports, dependencies, secrets, volumes or network connections.
Resource use is unchanged.
