# alfred 0.9.0 update

alfred now does arithmetic, unit conversions and calendar questions itself
instead of letting the model guess. It also tells the model the time each
message arrived. For the infra side, this is a new image tag and nothing
else. There are no migrations, and no new settings, secrets, dependencies,
connections, ports or volumes.

```yaml
handover_update: 1
service: alfred
from: 0.8.1
to: 0.9.0

before: []

changes:
  - change: changed
    path: components.alfred.image
    value: album.lan/alfred:0.9.0  # linux/amd64; see Open questions

after: []

verify:
  - "Owner sends 'what's 347 times 28.5?'  ->  the reply says 9889.5, and docker logs alfred shows 'turn <n> tool call #1 alfred_calculate {\"expression\": \"347 * 28.5\"} -> ok: 347 * 28.5 = 9889.5'"
  - "Owner sends '350 F in celsius?'  ->  about 176.7 °C, from an alfred_calculate call with from_unit/to_unit in the log"
  - "Owner sends 'what weekday is 3 March 2027?'  ->  Wednesday, from a 'tool call #1 alfred_date {\"op\": \"weekday\", ...} -> ok: 3 March 2027 is a Wednesday.' log line"
  - "Owner sends 'what time is it?'  ->  the current local time (ai.timezone), with no '[Mon 9 Nov 14:05]'-style stamp at the start of the reply"

clients: none
rollback: >
  Pin album.lan/alfred:0.8.1. No database or configuration changes, so
  nothing else to undo. History written under 0.9.0 reads normally on 0.8.1,
  which simply doesn't show message times.
```

## Details

**New tools.** `alfred_calculate` (arithmetic, plus unit conversion through
the bundled `pint` library) and `alfred_date` (days between dates, shifting
dates, weekdays, the time in other timezones) run inside alfred. They call
no other service and need no network access. They are offered on every turn,
`/ask` turns included. The expression evaluator never runs model input as
code, and it refuses huge numbers at once, so a bad call can't stall the
worker.

**Message times.** Messages from the owner, from services (`/notify`,
`/ask`) and delivered reminders now reach the model starting with the local
time they were recorded, in `ai.timezone`, such as `[Mon 9 Nov 14:05]`.
Stamps come from the existing `entries.created_at` column, so there is no
migration. They apply to the history from before the upgrade too. The system
prompt still only gives the date, so `ollama-gpu` keeps reusing its cached
prompt prefix as before.

**Resources.** Each turn's context grows by about 2,100 characters for the
definitions of the two new tools, `alfred_calculate` and `alfred_date`,
about 600 for the system prompt, and about 20 per history message. The turn
context log line (`turn <n> context: ... alfred <chars> ...`) shows it. pint
adds about 2 MB of memory. It loads its unit table on the first conversion
after a start, which adds up to half a second to that one call, and writes
nothing to disk.
