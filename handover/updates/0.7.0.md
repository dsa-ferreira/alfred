# alfred 0.7.0 update

alfred can now search the web through the homelab's SearXNG and read web
pages. For the infra side, this release brings a new image tag, two new
outbound connections (SearXNG on `oracle.lan`, and public web servers for
page fetch), a new `[web]` section in `alfred.toml` and a higher
`max_requests_per_turn`. There are no new secrets, dependencies, ports,
volumes or migrations.

```yaml

        Called only when the model decides to search, typically once or twice
        per web question. Configured as web.searxng_url.

    why: New outbound connection. alfred's host must reach oracle.lan on port 80.
  - change: added

    value:
      direction: uses

        Page fetch: plain GET requests to public web servers on the internet,

        from links the owner sends. alfred resolves each host itself through
        the container's normal DNS and refuses private, loopback, link-local,
        CGNAT and other non-public addresses, so it never fetches LAN hosts.
        User-Agent "alfred/0.7.0", no cookies, no auth. Each fetch has a
        20-second limit and stops after 5 MB.
      tolerates_cold_start: true
    why: >
      New outbound connection. alfred's host needs outbound HTTP (80) and
      HTTPS (443) to any public address, plus DNS resolution of public

      existing rule. URLs on other ports fail with an error the model reports;
      allowing them is optional.
  - change: changed
    path: placement.reason
    value: >
      One small Python process with no volumes. Needs outbound internet:
      HTTPS to api.telegram.org, and HTTP/HTTPS to public web servers for page

      (single AI worker, and Telegram long polling allows only one poller per
      bot).
```

## Details

**The `[web]` section** of the rendered `alfred.toml`:

```toml
[web]
searxng_url = "http://oracle.lan"   # SearXNG; alfred queries {searxng_url}/search?format=json
search_results = 5                  # results listed per search
fetch_page_chars = 8000             # page text per fetch result (~2.5k tokens)
fetch_timeout_s = 20                # one search, or one fetch including its redirects
fetch_max_bytes = 5000000           # largest page download
```

As for the other URLs, use plain HTTP, not `https://*.lan`: the image does not
trust the homelab CA. `searxng_url` must be an `http://` or `https://` URL
with a host; anything else stops alfred at startup with an error naming
`web.searxng_url`.

**Which pages alfred fetches.** Only URLs that appeared in a search result
earlier in the same message, or that the owner wrote in the chat (for `/ask`,
in the calling service's prompt). The model can't open other URLs, including
links it finds inside pages. On top of that, every request and every redirect
is checked, and any host that resolves to a non-public address is refused.
So alfred can't reach LAN services through fetch, even if a search result
points at one. An egress rule that blocks private ranges for web traffic
would add defence in depth but isn't required.

**Load.** A web question takes 2 to 5 more requests to `ollama-gpu` than
before, and each page read adds about 2.5k tokens of context. Turns get
slower but stay within the existing 300-second request timeout. Downloading
and parsing a page (lxml/trafilatura) briefly uses more CPU and memory. This
hasn't been measured; the 5 MB download cap bounds it.

**Logging.** Each fetch logs one INFO line with the final URL, HTTP status,
content type and size, plus a second line with the length of the extracted
text. Refused fetches log the reason. Search failures log a WARNING (`web
search failed: ...`). Queries and URLs are not secret.

## Open questions

- `album.lan/alfred:0.7.0` must be pushed before deploying this update. Run
  `make push` from this repo once the 0.7.0 version bump is committed.
- **`album.lan/alfred:0.6.0` was overwritten by mistake** with a build of this
  release's code (it reports itself as 0.6.0). A host that already runs 0.6.0
  keeps its old image until it pulls again. Until the real 0.6.0 is pushed
  again from its git commit, don't re-pull 0.6.0, and know that rolling back to
  it gives 0.7.0's code. That code also runs with the 0.6.0 config, using the
  `[web]` defaults.
