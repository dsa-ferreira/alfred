# alfred 0.4.0 update

alfred now remembers ended conversations. When the owner ends one, alfred has
the model write a short title and summary, embeds them with the embedding
service on `ragman.lan`, and stores them in Postgres. The owner can later ask
alfred to find and recall an earlier conversation. For the infra side, this
release changes three things. The database needs the `pgvector` extension, so
the Postgres image changes and a superuser has to create the extension once.
alfred gets a new HTTP dependency on `ragman.lan`. And `alfred.toml` gains a
`[memory]` section and `[ai] timezone`. There are no new secrets, ports or
volumes.

```yaml
handover_update: 1

    restart it. Use the -bookworm variant instead if the current image is
    bookworm-based; see Details.
  - >
    As the Postgres superuser, in the alfred database, run once:
    CREATE EXTENSION IF NOT EXISTS vector;
    (e.g. docker exec <postgres> psql -U <superuser> -d alfred -c 'CREATE EXTENSION IF NOT EXISTS vector;')
```

## Details

**Postgres image.** `pgvector/pgvector:0.8.7-pg17-trixie` is the official
Postgres 17 image with pgvector added, so it is a drop-in for `postgres:17`:
same data directory format, same environment variables, same init-script
directory. The suffix is the Debian release. Pick the one that matches the
image the database runs on now (`postgres:17` itself has been trixie-based
since 2025; `pgvector/pgvector:0.8.7-pg17-bookworm` also exists). Changing
Debian release changes glibc, and Postgres would then warn about collation
version mismatches on existing databases. alfred's tests run against
`0.8.7-pg17-trixie`. If the Postgres instance is shared, the extension
only exists in databases where it is created; other databases are not
affected.

**What `[memory]` does.** All keys are optional. The defaults are the
recommended values:

```toml
[ai]
# ...existing keys...
timezone = "Europe/Lisbon"            # the owner's zone: today's date in the prompt, search dates

[memory]
# summary_model = "gemma4:12b-it-qat" # default: [ai] model. A different model would make
                                      # ollama-gpu swap models on every ended conversation.
embedding_base_url = "http://ragman.lan"   # plain http: the image doesn't trust the homelab CA
embedding_model = "nomic-embed-text:v1.5"  # the model ragman serves (768 dimensions)
embedding_timeout_s = 30              # ragman is CPU-only but always loaded; one short text per call
document_prefix = "search_document: " # nomic's task prefixes; change only with the model
query_prefix = "search_query: "
recall_max_chars = 32000              # ~8k tokens: a recalled conversation fits the owner's 32k budget
summary_input_max_chars = 60000       # longer transcripts keep their start and end for the summary
search_results = 5                    # enough to choose from, short enough for a 12B model
```

Changing `embedding_model` later needs no migration: alfred re-embeds every
archived conversation in the background, and until a conversation is
re-embedded it is found by keywords only.

**Load.** Ending a conversation costs one extra request to ollama-gpu, which
is awake at that point because it just answered. The owner's next message
waits for it, a few seconds. Search embeds the query on ragman, never on
ollama-gpu. If a summary or embedding fails, alfred retries in the background
with the `[queue]` backoff (30 s doubling to 15 min), without messaging the
owner and without delaying owner messages.

**Downtime.** None beyond the usual restart. Migration 0002 adds nullable
columns and indexes to small tables, which takes well under a second.
